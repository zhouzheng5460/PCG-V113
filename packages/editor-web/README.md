# 规则验证器（editor-web）

一个单页应用，把**看不见的验收规则**变成可拖、可看、当场变色的东西。

## 为什么有它

在这之前，所有验证都只有两种形态：

| 手段 | 局限 |
| --- | --- |
| 控制台文本（`run.ts` / `batch.ts`） | R1–R11 判了什么、判得对不对，只能逐行读 |
| 静态 HTML 报告（`batch.html` / `reverse.html`） | 能看，但不能改，看不到"改一下会怎样" |

于是有三件事一直没法当场确认：

1. **规则判得对不对** —— 比如 R7 说"没有车行可达"，画出来到底长什么样？
2. **ready 预测对不对** —— `ready.ts` 的家族模型说商场族"街道无关"，怎么直观验证？
3. **楼位切得合不合理** —— E1–E6 说"浪费 8%"，那 8% 在哪？

这个页面把三层同时摆在一个画布上，拖一条街出去，右边立刻变色。

它**不是编辑器**：不调 dotnet、不写文件、不持久化。编辑能力只保留到"拖动几何、看规则反应"为止。
真正的编辑器是合并计划的 P2，这个页面会在那时长大成它（补 7 类渲染通道 + 130 生成器选择器），不用推倒。

## 跑起来

```bash
# 构建：编译 TS（浏览器不认 .ts）+ 打包夹具 + 顺手产出内联版
node packages/editor-web/build.mjs
```

构建完有两种打开方式，**推荐第一种**：

| 方式 | 做什么 | 依赖 |
| --- | --- | --- |
| **双击 `规则验证器.html`** | 自包含单文件（样式/数据/脚本全内联），`file://` 直接跑 | **无** |
| `node packages/editor-web/serve.mjs`，或双击 `start-server.cmd` | 起 http 服务 → http://127.0.0.1:8765/ | 一个活着的终端 |

> **为什么默认给了单文件**：这里踩过坑。http 版是零依赖静态服务器，但那个 node 进程会随
> 启动它的终端/会话被回收，用户看到的是 `ERR_CONNECTION_REFUSED`；换 WMI 创建进程、
> 计划任务去脱离父进程都被安全策略挡了。那就别跟沙箱较劲 —— 直接把"必须用 http"这个前提消掉。
>
> ES module 和 `fetch` 在 `file://` 下会被 CORS 拦掉（报 "Failed to fetch bundle.json"，
> 看着像数据没打包，其实不是）。`standalone.mjs` 做两件事就绕开了：把 20 个编译后的
> module 打成**一个经典脚本**（无 CORS），把 `bundle.json` 内联成 `window.__BUNDLE__`
> 并短路那一次 `fetch`。**源码一行没改**，只是语句级改写。
>
> 代价：单文件不会热更新，改完要重跑 `build.mjs`。要边改边看就用 http 版。

`standalone.mjs` 只认本项目实际用到的四种顶层语法（见文件抬头），遇到别的导出形式**直接抛错**
而不是产出一个"看起来能跑"的残包 —— 白屏最难查。


## 三层验证

| 层 | 数据来源 | 画布上怎么看 | 右栏怎么看 |
| --- | --- | --- | --- |
| **规则层** | `street-rules/src/rules.ts` 的 `validateCase` | 绿点=贴合点 + 法向短线；红边=该临街却没贴合点 | R1–R11 逐条亮灯，红=错、黄=提醒（R10/R11） |
| **判定层** | `street-rules/src/ready.ts` 的 `predictReady` | — | 我们预测 vs C# 基线并排，不一致直接标红 |
| **几何层** | `slots/src/cut.ts` + `validate.ts` | 色块=楼位、紫色虚线=宗地、紫底=宗地范围 | 楼位数、面积、边角料比例、E1–E6 |

C# 基线来自 `tools/batch/ready-baseline.json`（由 `build.mjs` 从真实 `--emit` 产物固化），
所以**页面本身不需要 dotnet**。

## 几个特意做的设计

**句柄必须和 SVG 一起产出**（`canvas.ts` 的 `CanvasResult.handles`）。
命中测试和绘制分开算，只要有一处少了个 padding，用户就会发现"看着在这、拖的是那"。

**拖动期间冻结视图**。
顶点一拖出去 bbox 就变，整张图会重新缩放，手柄从鼠标底下跑掉——摸起来像"拖不动"。
松开后解除冻结再自适应一次。

**句柄小、半透明**。
22 条街 × 3 个句柄 = 66 个点，画大一点整个画布就只剩黄点。悬停时由 CSS 加亮。

**宗地描边画在楼位之上**，但宗地底色垫在楼位之下。
第一版把虚线垫在下面，结果楼位是从宗地切出来的、边界几乎贴合，虚线被实边整个盖掉。

## 目录

```
src/view.ts     坐标变换（世界↔屏幕）+ 反向变换，供命中测试用
src/canvas.ts   画布 SVG + 句柄表
src/app.ts      状态、计算、面板、拖拽事件
build.mjs       编译 + 打包夹具（自动找 tsc）
standalone.mjs  内联版打包器（ES module → 经典脚本，bundle.json → 内联）
verify-standalone.mjs  无头 Edge 验内联版：file:// 直开、抓报错、数 DOM
serve.mjs       零依赖静态服务器（http 版，可选）
start-server.cmd  双击 = 起服务 + 开浏览器
规则验证器.html   内联版产物（双击即开，无需服务）
public/         产物目录（js/ 编译输出、data/bundle.json）
```

## 已知限制

- 只有 4 份地块带宗地（`mallPark` / `outdoorMall` / `shopsPark` / `stripMall`），其余 50 份切不了楼位
- 街道只能拖端点和平移整条，不能增删；地块只能拖顶点，不能加点
- 130 个生成器里只有 32 个有实测样本，其余在右栏显示"未核实"（`ready.ts` 的 `unknown`，刻意不猜）
- 没有 undo/redo，靠「还原这份地块」
