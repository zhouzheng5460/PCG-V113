一 · ready 到底由什么决定

这一节是整个验证的地基。前一轮在这里搞错了：把「出入口可达」当成 ready 的判据去套所有生成器， 结果在商场/市场族上全线假阳。逐行核对 Emit.cs:95-111 后，真实的因果链只有三步：

given  = input.Markers.Count                  // 烘焙工具塞的 / 玩家点的
sug    = gen.SuggestMarkers(input)            // ① 建议 —— 只有这一步碰街道
if (sug非空 && given==0) input.Markers += sug // ② 建议被写回成真 marker
ready  = gen.CheckReady(input)                // ③ 只数 marker，从不看街道

所以 ready ⇔ CheckReady(given>0 ? given : suggest)。而 suggest 是否为空， 由两个互相独立的开关决定（SuggestMarkers 与 CheckReady 是两套平行分家，互不通用）：

四 · 街道真正的作用点不是 ready

既然 ready 只数 marker，那街道规则到底管什么？在 LayerBase.cs:521-531：

if (!CheckReady(input).Ready) TrimOutlineEnds(plan, region, unplacedInset);
else if (!CheckReady(带空markers).Ready) { /* 只保留 marker 附近 5 m 内的接轮廓 */ }

ready=no 不是失败，是「路径不许接到街上」的降级开关。布局照样生成，只是内部路网封在轮廓内。 这就是之前观察到的"静默降级"的精确机制。量出来的结果：

0
ready=no 的 1 份，接到街的路径条数
16
ready=yes 的 53 份，接到街的路径条数

左卡片恒为 0，那正是 TrimOutlineEnds 在起作用。但别把它当成"我们算对了"的证据—— 这里数的是已有 startAttach/endAttach 的路径条数，与 ready 是两条独立的线： 右卡片的 16 条远小于 53 份，正因为建议出来的口 AttachId 恒为 -1 （Entrances.cs:371 的 Suggested = true），只有玩家或烘焙工具给的口才真接街。

五 · 扰动实验（看断言本身成不成立）

54 份真实数据是 53 收 1 拒，样本极度不平衡，一致率高说明不了区分力。 但这里扰动实验的目的已经变了：不是"证明判据对"，而是检验断言本身—— 每一族都有一条可被否证的断言：

家族断言
shop / marketready 次数应正好等于有给定口的次数 —— 街道怎么改都不动
parkingready 次数应介于 0 与总数之间 —— 街道既抬得起也打得到
typed / noneready 次数应等于总数 —— 恒 ready

最后一个变体「无街·无给定口」是最狠的一刀：把街道全删光。公园族应当照旧 ready， 因为 Entrances.Suggest 在候选为空时会兜底"最长边的中点"（Entrances.cs:239-259）—— 这正是 ready.ts 里 typed 族那条结论的结构性依据，而不是经验。
