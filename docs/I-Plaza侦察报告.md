## 2. 五个发现（按重要性排）

### 2.1 **Plaza 完全不产路径中心线**

9 例 `nets` **全为 0**。circulation 被编码在 **142 块 `plaza/surface.paving` 面**里，
不是"园路 + 宽度"的线性网络。

→ **这直接否掉了"Plaza 会逼出通用 PathNetwork"的预期。**
按"原语扩展需要 ≥2 个生成器的证据"这条原则，**现在不该做 `PathNetwork`**：
`parking.ts` 里的 `connectAisles` 继续留在 parking，不急着抽象。

### 2.2 铺装比例由**障碍物**与**形状不规则度**主导，不是由 plaza 自己的规则主导

| 工况 | 铺装% |
| --- | --- |
| 规则多边形、无建筑 | **97~99%** |
| 同上 + 4 栋建筑（r6） | **80.9%**（`SiteSafety` 裁掉） |
| 真实不规则地块 + 11 栋建筑 | **53.4%** |

→ **`surface coverage 98~102%` 这条门禁对 plaza 直接不成立。**
和 parking 的 `part6` 是同一类假门槛。plaza 的覆盖必须**按输入条件**判：
有障碍物就该低。建议改成"铺装 + 绿化 + 未被障碍物占用的余量 ≈ 地块"这种**自洽**判据，
而不是绝对百分比。

### 2.3 面片数量大 ≠ 碎片化

142~157 块面，但**连通块恒为 1**，最大开阔占 54~100%。
面片是网格切分方式，不是设计碎片化。所以 plaza 的"fragmentation"指标应当用
**连通块数 + 最大连通占比**，不能用面片数。

### 2.4 出入口永远接得上

9 例里 `accessPoint` 全部落在铺装上（≤12 m），中位距离 0.3~6.6 m；只有 `s1-acute`
（锐角楔形）出现 1 个口未接（距离 > 12 m）。说明"出入口 → 铺装"是本生成器最稳的一环，
但**退化锐角会失手** —— 这正是 stress 用例的价值。

### 2.5 focus 与面积强相关，edge 与面积弱相关

- `centerpiece`：≥1120 m² 才有 1 个，216 m² 时为 **0**
- 树 32~57（随面积涨）、长椅 15~25、灯 22~32：**密度大致稳定**
- 灌木 0~8、花池 0~32：**波动大**，更像是"A/B 变体"而非连续量

→ Plaza V1 的物件规则应当分开处理：`centerpiece` 用**阈值**（面积够不够），
树/椅/灯用**密度**，灌木/花池用**离散变体**。

## 3. 对 Plaza V1 的门禁建议（修订用户草案）

| 项 | 用户草案 | 建议 | 理由 |
| --- | --- | --- | --- |
| surface coverage | 98~102% | **自洽判据**：铺装+绿化+障碍物占用 ≈ 地块（±2%） | 2.2：有障碍物时 golden 只有 80.9% / 53.4% |
| surface overlap | < 0.5% | 保持 | parking 已能到 0.02% |
| entrance reachability | 100% | 保持（但允许 stress 失败） | 2.4 |
| main path connected | 100% | **删掉**（没有 path） | 2.1 |
| regions non-overlap | 100% | 保持 | — |
| objects inside region | 100% | 保持 | — |
| hardscape ratio ±20% | 保持 | 但要**按工况分组**（有/无障碍物） | 2.2 |
| green ratio ±20% | 保持 | golden 只有 0.5~2.6%，绝对值极小，用**绝对容差**（±150 m²）更合理 | 0.5% 相对误差没意义 |
| productive path length ±25% | **删掉** | 没有 path | 2.1 |
| region count | 观测 | 保持观测 | — |

## 4. Plaza V1 预期的原语组成（写下来，作为 V1 的验收对照）

| 原语 | 用途 | 现状 |
| --- | --- | --- |
| `polygon.ts` | `offsetRing` 退线、`clipVSlab` 分带、`minAreaBox` 定朝向 | ✅ 已有 |
| `boolean.ts` | 障碍物挖洞、铺装与绿地的互补（`differenceRegion`） | ✅ 已有 |
| `splitRegion` | L 形/凹形的多朝向分区 | ✅ 已有（18 项测试） |
| `scatter.ts` | 树/椅/灯/灌木的沿边与面内散布 | ✅ 已有 |
| **新增？** | focus 落点（中心物件）。可能就是 `centroid + 内缩`，不需要新原语 | 待验证 |
| ~~PathNetwork~~ | **不需要**（plaza 无 path） | 2.1 |

→ 预期 **0 个新原语**。如果实现时发现需要第 3 套几何，说明原语层没站稳 ——
那要停下来review，而不是继续写。

## 5. 复现

```bash
node tools/golden/gen-plaza-cases.mjs   # 造 9 份用例（固定 settings）
node tools/golden/emit.mjs              # 烘 golden（每份跑两次，逐字节比对）
node tools/golden/gen-cohorts.mjs       # 合并 cohort 标注
node packages/site-gen/src/cli/recon.ts plaza          # 本报告的源表
node packages/site-gen/src/cli/primitives.ts parking   # 原语复用报告
```
