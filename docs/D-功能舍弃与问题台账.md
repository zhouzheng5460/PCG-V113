# 功能舍弃与问题台账

> **第一性原则**：凡界面输入或算法与 Placemaker 冲突，**以 Placemaker 为准**。
>
> 但"以它为准"不等于"没有代价"。每一条偏离、每一处舍弃、每一个由此产生的新问题，都必须在这里留一条记录，编号**永久不复用**。目的是：三个月后回看，能一眼知道"这里为什么不按我们原来的做法"。
>
> 判定流程：**能移植的照搬 → 不能移植的降级并记账 → 降级后产生的连锁问题也记账**。

---

## 0. 字段定义

| 字段 | 含义 |
| --- | --- |
| 编号 | `D-` 舍弃/降级、`Q-` 问题、`R-` 风险 |
| 类别 | 输入契约 / 算法 / 渲染 / 交互 / 数据 / 工程 |
| 现象 | 具体发生了什么（带数字） |
| 处置 | 照搬 / 降级 / 舍弃 / 延后 |
| 影响面 | 哪些生成器或功能受害 |
| 替代方案 | 我们拿什么顶上 |
| 验证 | 怎么知道"顶上去了"（可执行） |
| 状态 | 待定 / 已定 / 已实现 / 待复核 |

## 4. 维护规则

1. **先记账，再动手**。任何"这里和原来不一样"的决定，提交前必须开一条。
2. **编号不复用**。作废条目保留，状态改「已废弃」并写原因。
3. **每条必须有验证**。写不出验证方式的条目，说明还没想清楚，状态留在「待定」。
4. **P2 结束做一次总复核**：把「已定」逐条对照代码，确认真的按记录执行了——台账最大的价值是防止"说好降级，实际偷偷按老的来"。
5. **已知待查清单**（下次开工先补）：D-017（哪 2 个生成器无输出）、D-005（配方语料能否脱离游戏实体）、`civic` 用地的 zone 映射（建筑规范 §4 标"低置信"）、Q-014（切分时如何避免产出无临街碎片）。

6. **被真实数据推翻的结论，必须就地改写，不要留在原地当"经验"**。已经发生过三次：
   - 「宗地进深必是 8 m 整格」（合成用例得出的，真实数据全是 17/25/33/14）→ D-019
